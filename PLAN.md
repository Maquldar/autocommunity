# AutoCommunity — план разработки

Источник: ТЗ v1.0. Соцплатформа для автомобилистов: карта, сообщества, SOS-помощь, автосервисы, рейтинг доверия.

---

## 0. Ключевые решения до старта

| Решение | Рекомендация | Почему |
|---|---|---|
| Мобильный фреймворк | **Flutter** | Один код на iOS/Android, хорошие карты и push, быстрее для маленькой команды |
| Backend | **NestJS + PostgreSQL + PostGIS** | PostGIS нужен для поиска "ближайших в радиусе" (SOS, карта) |
| Realtime | **WebSocket (Socket.IO) + Redis** | Чаты и живые позиции на карте |
| Карты | **Mapbox** | Гибче стилизация, дешевле Google на больших объёмах |
| Файлы | **Cloudflare R2** | Нет платы за egress |
| Push | **FCM** (+ APNs через FCM) | Как в ТЗ |
| Auth | Телефон + SMS (Twilio / локальный SMS-провайдер), Google, Apple | Apple ID обязателен, если есть Google (требование App Store) |

## 2. Этап 1 — MVP (3–4 месяца)

### Спринт 1–2: Фундамент (4 недели)
- [ ] Backend-каркас: NestJS, TypeORM/Prisma, миграции, логирование
- [ ] Auth: регистрация по телефону + SMS-код, Google, Apple ID
- [ ] JWT access + refresh, защита от brute force / SMS-спама
- [ ] Профиль: фото, имя, никнейм, город, описание
- [ ] Автомобиль: марка, модель, год, госномер (необязательно)
- [ ] Mobile: навигация, onboarding, экраны auth и профиля

### Спринт 3–4: Карта и приватность (4 недели)
- [ ] Передача геопозиции (фон/foreground, интервал, экономия батареи)
- [ ] Карта пользователей (Mapbox) с кластеризацией
- [ ] Режимы приватности: Скрыт / Сообщество / Друзья / Всем (проверка на **сервере**, не на клиенте)
- [ ] Друзья: заявки, список
- [ ] Гео-запросы в PostGIS (радиус, bbox)

### Спринт 5–6: Сообщества (4 недели)
- [ ] CRUD сообществ, открытые/закрытые, заявки на вступление
- [ ] Роль модератора: участники, заявки, удаление контента
- [ ] Фильтры на карте: сообщество / несколько / друзья / марка авто
- [ ] Групповой чат сообщества

### Спринт 7–8: SOS и чат (4 недели)
- [ ] Создание SOS: тип, описание, фото, координаты
- [ ] Алгоритм: радиус → ближайшие → push → отображение на карте
- [ ] Карточка SOS: имя, рейтинг, авто, фото, расстояние, время
- [ ] Кнопки: Помочь / Позвонить / Написать
- [ ] Жизненный цикл SOS: создан → принят → в процессе → закрыт / отменён / истёк
- [ ] Личные чаты: текст, фото, геолокация, голосовые

### Спринт 9: Рейтинг и отзывы (2 недели)
- [ ] Взаимная оценка после закрытия SOS (1–5 + комментарий)
- [ ] Рейтинг доверия: помощь, отзывы, активность, стаж
- [ ] Штрафы: жалоба (−10), фейковый SOS (−50)
- [ ] Ограничение отзывов (только после подтверждённой помощи)
- [ ] Жалобы на пользователей

### Спринт 10: Админка и релиз (2–3 недели)
- [ ] Web Admin: пользователи (поиск, блок, предупреждения), сообщества, SOS-история
- [ ] Antifraud v1: лимиты SOS, детект фейков, блокировки
- [ ] Нагрузочное и security-тестирование
- [ ] Закрытая бета (TestFlight / Google Play internal)
- [ ] Публикация в App Store и Google Play

**Критерий готовности MVP:** пользователь регистрируется, видит других на карте, вступает в сообщество, создаёт SOS, получает помощь, ставит оценку.

Добавлено относительно ТЗ: `Friends`, `Chats`, `RatingEvents`, `Reports`. Без них не работают режим «Друзья», чаты, прозрачный рейтинг и жалобы.

## 6. Риски и дыры в ТЗ

1. **Холодный старт.** Карта и SOS бесполезны, пока рядом нет людей. Запускать в одном городе через сообщества и клубы (у тебя есть доступ к горному клубу на 400 человек, это готовый пилот для проверки механики).
2. **Объём MVP.** Регистрация + карта + сообщества + SOS + чат + рейтинг за 3–4 месяца реалистичны только для команды 4–6 человек. Для 2–3 человек это 6–8 месяцев. Если нужно уложиться, вырезать из MVP: голосовые, видео, закрытые сообщества.
3. **Безопасность и приватность.** Живая геопозиция водителей, с госномерами, это самый чувствительный кусок. Нужны: округление координат для режима «Всем», запрет показа госномера на карте, возможность быстро скрыться, согласие и политика ПДн.
4. **Злоупотребление SOS.** Риск фейков, ловушек (ограбления на пустой дороге) и спама. Нужны: верификация телефона, минимальный рейтинг для помогающих/просящих, кнопка «жалоба», проверка телефона и фото, возможность делиться маршрутом с контактом.
5. **Ответственность.** Если помощь привела к травме или ДТП, возникают юридические вопросы. Нужен дисклеймер в ToS: платформа не заменяет экстренные службы (103/112), для ДТП и угроз жизни кнопка «Вызвать 112».
6. **Формула рейтинга сломана.** `Рейтинг = помощь + отзывы + активность + стаж` без весов и потолка даёт накрутку и «вечных ветеранов». Нужны: веса, затухание со временем, потолок на «активность» и «стаж».
7. **Конфликт правил отзывов.** Пункт 13 ограничивает отзывы порогом рейтинга, а новичок с нулевым рейтингом не может его набрать, не получив отзыв. Нужна стартовая репутация или отдельное правило для верифицированных помощников.
8. **Фоновая геолокация.** Apple/Google жёстко ревьюят «Always» location. Нужно обоснование в ревью и разумный fallback (обновление только при открытом приложении).
9. **Apple ID.** Если есть Google/сторонний вход, Sign in with Apple обязателен в iOS.
10. **Стоимость SMS.** Дорого при массовом спаме. Rate-limit, CAPTCHA, лимит по IP/устройству.
11. **Модерация контента.** Фото, видео, чаты, лента требуют пайплайна модерации (жалобы + автофильтры), особенно для App Store.

## 8. Метрики успеха MVP

- Активация: ≥ 40% зарегистрированных заполнили профиль и авто
- Доля пользователей, открывших карту на 2-й день (D1/D7 retention)
- Время от SOS до первого отклика (цель: < 10 минут в городе пилота)
- Доля SOS, закрытых подтверждённой помощью
- Доля жалоб / фейковых SOS (цель: < 5%)
- Число активных сообществ и средний размер
